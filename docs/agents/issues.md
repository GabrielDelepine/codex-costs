# Issues

Follow the shared [writing style](../../AGENTS.md#writing-style) for titles, bodies, and comments.

- Write issues in English. Keep their length and structure proportional to the problem; headings are optional.
- Default to a short body explaining the problem, its impact, and the desired outcome. Add reproduction steps or evidence only when they help someone assess or reproduce it. Avoid repeating the title, background, or discussion; expand only for material uncertainty or complexity.
- Title the issue around the observed problem or user-facing limitation, not a proposed solution or development task.
- Start the body with the current behavior, the circumstances in which it occurs, and its impact. Include a concrete example or reproduction steps when useful. Distinguish confirmed observations from hypotheses.
- When useful, describe the desired outcome under “Expected behavior”. Add “Suggested solution” or “Suggested investigation” only when there is a useful proposal to discuss, and present implementation ideas as suggestions.
- Keep the issue focused on the problem and desired outcome. Put implementation details, changed files, commit summaries, and validation results in the PR.
- Include only necessary, redacted evidence. Never publish personal logs, prompts, credentials, or private conversation contents.

Use this convention directly; reading existing issues is not a prerequisite to creating or rewriting an issue.
